# Public API

This website has no backend of its own. All content is fetched from static JSON generated by the companion [developer-interview-handbook](https://github.com/rasoolzia/developer-interview-handbook) repository and published under `public/api/` on that project. This document describes the shape of that JSON as this frontend depends on it, and how the frontend types it internally.

The generator repository is the single source of truth for the actual schema. If this document and that repository's output disagree, the generator wins — update this doc, not your assumptions.

---

## Endpoints

```
public/api/
    manifest.json
    search-index.json
    <domain>/
        <topic>/
            en.json
            fa.json
```

### `manifest.json`

Top-level index of every domain/topic/language combination that exists, plus per-topic stats and a content hash (useful for cache invalidation).

```json
{
  "generatorVersion": "1.x.x",
  "schemaVersion": "x",
  "generatedAt": "2026-08-01T00:00:00.000Z",
  "languages": ["en", "fa"],
  "domains": {
    "frontend": {
      "label": "Frontend",
      "topics": {
        "css": {
          "label": "CSS",
          "languages": {
            "en": {
              "path": "frontend/css/en.json",
              "total": 37,
              "hash": "8af0f3a0fe"
            },
            "fa": { "path": "frontend/css/fa.json", "total": 37, "hash": "..." }
          }
        }
      }
    }
  }
}
```

Consumed by: `entities/domain/api/manifest.service.ts`.

### `search-index.json`

A flat array of every question across every domain, topic, and language — the dataset the `/search` page filters, paginates, and facets client-of-server-side (see [`architecture.md`](./architecture.md) for the server-first rendering model).

```json
{
  "id": "css-001",
  "slug": "what-is-the-css-box-model-and-what-are-its-components",
  "title": "What is the CSS box model and what are its components?",
  "domain": "frontend",
  "topic": "css",
  "language": "en",
  "difficulty": "Easy",
  "categories": ["Fundamentals"],
  "readingTime": 1
}
```

Note: `label` (topic display name) and `path` (question URL) are **not** included — both are derivable from other fields (`topic` → `getTopicLabel()`; `language`/`domain`/`topic`/`slug` → `ROUTES.question()`), so they're computed on the frontend instead of duplicated in every one of the ~900+ search-index entries.

Consumed by: `entities/search/api/search.service.ts` → mapped by `views/search/lib/search.mapper.ts`.

### `<domain>/<topic>/<lang>.json`

The full record for one topic in one language.

```json
{
  "version": 1.6,
  "meta": {
    "domain": "frontend",
    "topic": "css",
    "language": "en",
    "label": "CSS"
  },
  "content": {
    "title": "CSS Interview Questions",
    "categories": ["Fundamentals", "Layout", "..."],
    "difficulties": ["Easy", "Medium", "Hard"]
  },
  "hash": "8af0f3a0fe",
  "stats": {
    "total": 37,
    "byDifficulty": { "easy": 2, "medium": 15, "hard": 20 }
  },
  "questions": [
    {
      "id": "css-001",
      "slug": "what-is-the-css-box-model-and-what-are-its-components",
      "title": "What is the CSS box model and what are its components?",
      "difficulty": "Easy",
      "categories": ["Fundamentals"],
      "domain": "frontend",
      "topic": "css",
      "language": "en",
      "markdown": "...",
      "readingTime": 1
    }
  ]
}
```

Consumed by: `entities/question/api/question.service.ts` (topic list / question detail pages).

## Frontend Type Model

Both `search-index.json` items and per-question entries in a topic file share the same core fields. Rather than maintaining two independent, drift-prone interfaces, the frontend defines one base shape and extends it:

```ts
// shared/types/question-base.ts
interface QuestionBase {
  id: string;
  slug: string;
  title: string;
  domain: string;
  topic: string;
  language: Language;
  difficulty: string; // raw, language-native display text — see note below
  categories: string[];
  readingTime: number;
}

// entities/search/model
interface SearchItem extends QuestionBase {}

// entities/question/model
interface Question extends QuestionBase {
  markdown: string;
  tags?: string[];
}
```

A shared view-model, `QuestionCardItem` (`entities/question/model/question-card.model.ts`), is derived from `QuestionBase` via `Omit<QuestionBase, "slug" | "domain">` plus a computed `href` — this is what the single, reusable `QuestionCard` component actually renders, regardless of whether the data came from `search-index.json` or a topic file.

## Difficulty: raw text vs. canonical value

`difficulty` in the raw JSON is **display text in the source language** — `"Easy"` in English content, `"آسان"` in Persian content — not a normalized enum. This is intentional: `categories` is also freeform, per-language text with no fixed set, so difficulty is treated consistently with it rather than as a special case.

This means `difficulty` must never be used directly as a URL param or filter key (`?difficulty=آسان` and `?difficulty=Easy` would represent the same concept but produce different, language-dependent URLs). Wherever a canonical, language-independent value is needed — filter facets, URL state — it's derived on the fly via:

```ts
// entities/question/lib/canonical-difficulty.ts
toCanonicalDifficulty(raw: string): "easy" | "medium" | "hard"
```

This keeps the _value_ language-independent (`?difficulty=easy` means the same thing on `/en/search` and `/fa/search`) while the _label_ shown to the user stays exactly whatever the content author wrote for that language.

## Validation

Fetched JSON is validated at the boundary with Zod (`shared/api/schemas`) before it's trusted anywhere downstream — the generator repository guarantees shape at build time, but the frontend doesn't assume that guarantee holds at runtime (network issues, stale caches, a future schema change landing before this repo is updated).

- `DifficultySchema` — currently `z.string()`, since difficulty is freeform per-language text (see above), not a fixed enum
- `LanguageSchema` — `z.enum(LANGUAGE_CODES)`, matching `shared/config/i18n`

If the generator's output shape changes, update the corresponding schema in `shared/api/schemas` first — TypeScript and Zod will then surface every place in the frontend that needs to change as a result.
